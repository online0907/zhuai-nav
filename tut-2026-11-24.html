7.用 n8n 搭 AI 線索評分工作流：收到詢問自動打分、分流

完整手把手教程：網站或 WhatsApp 收到詢問後，n8n 用 Webhook 接單、AI 抽取行業／預算／緊急度等欄位、Code 節點按規則打分，60 分以上進銷售、以下進培育，附完整評分代碼可直接複製。

來源：DEV · hashim_khan

3 步上手：
  1. 第 1 步：在 n8n 建工作流，加 Webhook 節點收詢問訊息。
  2. 第 2 步：加 AI 節點抽取結構化欄位（只輸出合法 JSON），再用 Code 節點按規則算分（例如有預算 +20 分）。
  3. 第 3 步：加 IF 節點按 60 分分流：高分進 CRM 跟進，低分進培育流程。

變現角度：線索評分是 B2B 客戶願意按月付費的剛需自動化；判斷邏輯放 Code 節點、理解放 AI 的分工模式，可複用到客服分流、訂單審核等多個場景，一套模板賣多家。

10.無臉 YouTube 六步生產線：按鏡頭選模型，Veo 3.1／Seedance 2.5／Hailuo 3 各有分工

把無臉影片拆成六道固定工序：寫分鏡腳本、逐鏡生成、同一聲音旁白、拼接混音、逐字字幕、AI 寫標題描述標籤；亮點是按鏡頭選模型——Veo 3.1 管對白與音效同步、Seedance 2.5 可生成 4–30 秒任意時長對齊旁白、Hailuo 3 管需清晰屏上文字的鏡頭。

來源：TrezaLabs

3 步上手：
  1. 第 1 步：先寫五行的 brief（主題、受眾、風格、長度、基調），再讓語言模型擴成「畫面＋旁白」的分鏡腳本。
  2. 第 2 步：按鏡頭特性選模型逐鏡生成，旁白全程固定同一個聲音。
  3. 第 3 步：拼接後用 Whisper 逐字上字幕，標題、描述、標籤留空讓模型按 transcript 寫，最後接排程觸發器做每日更新。

變現角度：六步生產線跑通後可批量接無臉頻道代運營，或把「每天一條」的排程能力賣給需要穩定更新的商家號；工具選型經驗本身也可做成付費教程。

12.7 個免費 ChatGPT 提示詞：從選副業到寫報價、拿到第一單

直接可複製的 7 個提示詞，覆蓋副業起步最難的三步：按自身技能與時間選方向、把想法寫成一句話報價、不靠猜法定價並找到前十個潛在買家；作者明言提示詞不能創造需求，只能加速決策。

來源：Medium · Lionheart Market

3 步上手：
  1. 第 1 步：把技能、每週時間、啟動預算、能觸達的人群填進提示詞 1，讓 AI 先提問再給 8 個 30 天內可測試的點子。
  2. 第 2 步：用提示詞 3 把選定的點子寫成五版一句話報價，挑最清晰的一版。
  3. 第 3 步：用提示詞 5 列出能找到前十個買家的人群與渠道，主動聯繫。

變現角度：這套提示詞本身就是可賣的數字產品雛形（作者文末即有付費提示詞包）；更實際的是用它快速驗證方向，省下「想兩個月、零行動」的時間成本。

14.Claude Code Skills：10 步做出你自己的第一個 Skill

對照 Anthropic 官方文件核查過（2026-11-03）的入門教程：Skill 就是一個裝著 SKILL.md 的資料夾，文中以 review-changes 為例，從建資料夾、寫 frontmatter 到測試觸發，10 步完整走完。

來源：aivibesofficial

3 步上手：
  1. 第 1 步：確認已裝 Claude Code，在 ~/.claude/skills/ 下建一個以任務命名的資料夾。
  2. 第 2 步：在裡面寫 SKILL.md：頂部 frontmatter 寫清描述（描述就是觸發條件），正文寫步驟與禁區。
  3. 第 3 步：開 Claude Code 問相關任務，確認 Skill 被列出並自動載入，再用斜槓加技能名直接調用測試。

變現角度：把重複工作寫成 Skill 就是把服務產品化：同一套 Skill 可複用到多個客戶項目，省下的 token 與時間直接變成利潤；也可把行業專用 Skill 打包成付費模板賣。

15.Skill 裝太多反而變慢：目錄成本與該留哪些的實測

實測向深度文：作者用自己的 Skill 目錄在 Claude Code 2.1.312 與 Codex CLI 上跑測試，結論是成本不在單個 Skill、而在目錄——每個已裝 Skill 每輪都佔一個位置，裝多了最不常用的會丟失描述；文件於 2026-11-18 對照官方文件複核。

來源：DEV · actuallyshipped

3 步上手：
  1. 第 1 步：盤點現有 Skill 目錄，關掉出於好奇裝的。
  2. 第 2 步：只保留重複貼過三次以上的流程型 Skill，事實類內容放回 CLAUDE.md。
  3. 第 3 步：每裝一個新 Skill 前先讀一遍它的內容，像審代碼一樣審，確認無越權指令再啟用。

變現角度：幫團隊做「AI 工具瘦身」本身就是一項服務：Skill 目錄越乾淨，Agent 出錯越少、token 花費越低；省下的模型成本與返工時間可以直接報價。

16.讓 Coding Agent 先寫行為再寫代碼：一段貼進 CLAUDE.md 的規則

來自 Reddit 的實用技巧：把一段「行為優先」規則貼進 CLAUDE.md 或 AGENTS.md，要求 Agent 對任何用戶可見的功能先寫驗收場景、轉成可執行測試、看著測試失敗再寫最小實現，適用 Claude Code、Codex 與 ChatGPT。

來源：Playbooks.bot（源自 Reddit 用戶 u/cannyshammy 的帖子）

3 步上手：
  1. 第 1 步：把文中那段 Behaviour-First 規則原文貼進項目指令文件。
  2. 第 2 步：提交一個示例場景文件，讓 Agent 照格式抄而不是自己發明格式。
  3. 第 3 步：每次改功能先自己寫場景、讓 Agent 轉測試並展示失敗，再放手讓它實現，跑 CI 長期守住行為。

變現角度：這是接 AI 開發單的品質護城河：行為先行讓交付物自帶測試、返工率大降，客戶更願意為「可驗證的交付」付高價；也可把這套規則寫進自己的開發服務標準流程裡對外展示。
