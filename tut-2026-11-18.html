1.用 AI Agent 每天早上替你找 Reddit 客戶，而且不會被版主封號

作者將一個 Reddit 客戶發掘角色交給 Grok Bot，每個工作日早上自動找出有人求助的帖文、查清各版規矩，再由人手改寫發佈。關鍵在於 Agent 只做研究和草稿，絕對不自行發帖，嚴格遵守各版的提及次數和 AI 回覆限制。

3 步上手：
  1. 將原文附帶的「Reddit customer-discovery role」提示詞貼入 Grok Bot（或 Muse、Dot、Duet），訂明 Agent 只做研究和草稿，絕對不可以自行發帖。
  2. 接駁 TrendsFast MCP 或 API（驗證賬戶一次性獲 100 個免費 credits，之後每月 50 個；社群簡報查詢免費），設定每個工作日 08:15（歐洲／阿姆斯特丹時間）出一次早報。
  3. 每朝在手機看 3 個回覆目標＋1 個發帖草稿，按各版簡報改寫成人話後用自己賬戶發佈；r/SaaS 這類嚴版要遵守「60 日內最多一次具名提及、不可以用 AI 寫回覆」的規矩。

變現角度：零成本為自己的 SaaS 產品做精準客戶發掘，在買家已經出聲求助的帖文裡面出現。作者自述 11 月 10 日起計已發 6 個回覆草稿、1 個帖文，帶來 2 個註冊、0 個付費客戶——數字雖細，但避開封號就是保住長期獲客渠道。

來源：Medium（Mees Tierolff，2026-11-18）

2.給 AI 100 美元叫它賺錢：兩日上架 3 個工具，收入 0 美元的誠實實驗

一名軟件研究員給 Claude（Fable 5.2）100 美元預算，指令是建立網上生意並獲利；AI 自行選了 Apify Store 上架 3 個小工具，兩日後交出第一份賬本：起始 100 美元、已花 0 美元、收入 0 美元、付費客戶 0 個。

3 步上手：
  1. 選一個已有買家的市集起步：Apify Store 免費上架、平台代收費，不用自己找客和接支付。
  2. 用 AI 寫一個細而具體的工具，例如原文的技術 SEO 審計（每 1,000 條 URL 收 5 美元）、斷鏈檢查（每 1,000 條連結收 1 美元）、網站技術偵測（每 1,000 個網站收 2 美元），附測試、HTML 報告和寫明做不到什麼的 README。
  3. 上架前先用市集搜尋 API 查競爭：作者事後才發現技術偵測類工具有約 250 個同類，最多人用的一個過去 30 日只有 61 個用戶——先做分銷（寫有用教學、開源程式碼、現成自動化模板），不要急著做第 4 個工具。

變現角度：按結果收費的小工具是典型的被動收入模型，但作者親身證明「上了架等於無人知」——先驗證需求和競爭密度再動手，否則只是免費幫市集充數。（賬本數字為作者原話）

來源：DEV（Claude 撰寫，人類擁有人原樣發佈，2026-11-18）

3.不用框架，4 個 Python 類別由零寫一個 AI Agent

將 Agent 拆解成「模型＋工具＋循環」，用約 330 行純 Python 寫一個發票審核 Agent，在本機 Qwen 模型上跑，40 張測試發票全部判對。沒有框架綁定，結構一目了然，是理解 Agent 運作最直接的方法。

3 步上手：
  1. 裝好 Python 3.11+、LM Studio（載入本機模型並開本地伺服器），再裝 pip install openai 作為連接 LM Studio 的客戶端。
  2. 照原文附錄抄 7 個檔案（約 330 行）：Tool（將普通函數包裝成模型讀得明的工具卡）、Agent（指示＋工具清單）、AgentLoop（問模型 → 跑工具 → 交回結果 → 再問的 for 循環）、Verdict（強制答案只可以是 APPROVE／REVIEW／REJECT 的固定 JSON 格式）。
  3. 執行 python -m post1_scratch.run_demo，用附帶的 4 張樣本發票驗證：乾淨發票批核、總數不對送人工覆核、重複發票和未授權供應商拒絕。

變現角度：這是接單做企業自動化的基本功——同一套結構換成查單、對賬、審批等任務，就可以向中小企收一次性開發費；本機模型運行，不用長期付 API 錢。（測試結果為作者自述：40/40 判決正確、平均每張發票 4.6 步、約 10 秒）

來源：DEV（rit_the_coder，2026-11-17）

4.不要叫一個提示詞做三份工：將工作拆成三個專責 Agent

一個長提示詞同時要抽事實、做判斷、寫文章，三個目標互相拉扯；拆成抽取、評估、起草三個 Agent，每個只做一次轉換，質素立刻穩定。改編自 Learnvoro 課程《Designing Multi-Agent Systems》第一課。

3 步上手：
  1. 將原本一個提示詞拆開：抽取 Agent 只將來源文件變成固定欄位的事實；評估 Agent 只憑抽取結果判斷是否越過門檻，不可以看原文（避免語氣影響判斷）；起草 Agent 只按評估結果寫回覆。
  2. 不要寫角色人設，寫「反目標」（anti-goals）：例如抽取 Agent 絕對不可以下判斷、起草 Agent 絕對不可以改事實。
  3. 寫提示詞之前，先填一張 Agent 規格表：每個 Agent 的角色、範圍、反目標、接受什麼輸入、保證什麼輸出；Agent 之間交接的是合約（結構化資料），不是整段對話紀錄。

變現角度：合規審查、客服回覆、文件處理這類「一錯就賠錢」的流程，才是企業願意付費的自動化；用這套拆分法接單，可以將一次過的提示詞工程變成可重複收費的多 Agent 系統。

來源：DEV（mgazar_，2026-11-17）

5.用 Next.js＋Claude Code 起一座 3D 城市，每棟樓都是一個 AI Agent

作者用 Claude Code 由零起了「Creator City」——一個 3D 城市裡面每棟建築都是一個幫創作者做事的 Agent，整個 2 小時 45 分鐘建造過程拍成免費課程，原始碼免費。

  2. 用 Claude Agent SDK 配置多 Agent 工作流，令不同 Agent 可以分工協作，再將整個應用部署上 Cloudhike.dev。
  3. 照課程 2:34:39 的部署一段將成品上線；原始碼免費，連結在 YouTube 影片簡介。

變現角度：創作者工具是最容易收訂閱費的賽道之一——將這個成品改成針對某一類創作者（例如短視頻、Newsletter）的工具包，或者將建造過程本身做成付費課程和模板出售。

6.起一個可上線的 RAG Agent（下集）：評分由 0.582 升到 0.729

上集做了評測框架，今集正式起 Agent：一個模型、三個工具、一個循環，專答新西蘭稅法問題，而且有數字證明每一步改動是否真的有用——「自信但答錯」由 5 宗減到 0 宗。

3 步上手：
  1. 承接上集的評測框架（harness/）和 Agent 資料夾（agent/），用 TypeScript＋Vercel AI SDK 起步，設定模型、法例資料庫和參數（每個答案上限 40 輪、8 分鐘、3 美元）。
  2. 先跑一次「無工具、一次查詢」拿底分，再加入三個工具和 ReAct 循環，逐次只改一個地方、每次用同一套評測對比。
  3. 看住兩個指標收貨：總分由 0.582 升到 0.729，「自信但答錯」由 5 宗減到 0 宗——改動無數字支持就不要保留。

7.用 Google ADK 起一個識讀公司文件的企業政策助手

以 Google Agent Development Kit（ADK）＋ Gemini＋ Google Drive 起一個企業政策問答 Agent，員工問人事、財務、安全等政策，答案有文件根據，不用再逐份 PDF 找。

3 步上手：
  1. 準備環境：Python 3.12、Visual Studio Code、去 Google AI Studio 拿 Gemini API Key，另開一個 Google Cloud 項目並啟用 Google Drive API，預備一個放公司政策文件的 Drive 資料夾。
  2. 用 Google ADK 寫 Agent、Gemini 做推理、詞彙檢索式 RAG（不用向量數據庫）讀 Drive 文件，再用 Streamlit 起一個對話式網頁介面。
  3. 完成本地版之後，按系列下集部署上 Google Cloud Agent Runtime，再接 Gemini Enterprise，變成全公司用得的服務；完整程式碼在作者的 GitHub 倉庫。

變現角度：這是最直接賣給中小企的 AI 服務：每間公司都有幾十份無人看的政策文件，幫他們起一個內部問答助手，收一次性開發費再加月費維護。

來源：DEV（gde，2026-11-16）

8.Skill、MCP Server 定 n8n 工作流？看誰發起工作就知選哪個

同一個任務——定期更新一張 Leeds 牙科診所名單——用三種形狀各做一次，講清每種在哪裡會斷，結論是三種一起用才最穩陣。

3 步上手：
  1. 先問「誰發起工作」：人在對話裡面臨時問東西 → 用 MCP 工具；Agent 按固定步驟重複做 → 寫 Skill（一個有 SKILL.md 的資料夾，Claude Code 讀 ~/.claude/skills，Codex 讀 .agents/skills）；定時無人值守 → 用 n8n 工作流（Schedule Trigger＋爬蟲節點＋去重過濾＋Google Sheets 節點，全程不用模型）。
  2. 不要犯三個錯：不要將排程寫入對話 Agent 的系統提示詞（無人開對話就不會跑）；不要將 2,000 行大爬取結果塞入對話工具（會超時或被截斷，改為每次給 20 行，或者交個結果連結）；不要為一次性問題寫 Skill（它的描述會由那刻起佔用每個對話）。
  3. 照作者的組合落地：n8n 每朝填表、MCP 工具在對話答跟進問題、Skill 保存「什麼才算是潛在客戶」的規則，讓任何 Agent 碰到這張名單都用同一標準。

變現角度：這是賣給本地商家的現成服務：定期交一張有電話、網址、評分的潛在客戶名單，客戶按名單或按月付費；懂得分辨三種工具，才不會將不合適的架構賣給客人。

來源：Medium（Recipe for Agents，2026-11-16）

9./last30days：一個指令，叫 AI 橫掃 Reddit、X、YouTube、HN 和 Polymarket 做調研

這個 Agent Skill 不信編輯、只信群眾：一次過搜 Reddit、X、YouTube、TikTok、Hacker News、Polymarket 等十幾個平台，按讚好和真金白銀的市場賠率評分，再合成一份有根據的簡報。11 月 17 日登上 GitHub Trending。

3 步上手：
  1. Claude Code 用家執行 /plugin marketplace add mvanhorn/last30days-skill 再 /plugin install last30days；其他 Agent 宿主（Codex、Cursor、Copilot、Gemini CLI 等）執行 npx skills add mvanhorn/last30days-skill -g。
  2. 直接打 /last30days <主題>，例如會面前查一個人、開會前查一間公司、起產品前查一個痛點；Reddit、HN、Polymarket、GitHub 零配置即用。
  3. 跑一次設定精靈解鎖 X、YouTube、TikTok 等來源（自備 API Key 或瀏覽器登入），再按需要加 --hiring-signals 等選項，例如找公司招聘頁暗藏的未發佈動向。

變現角度：會前調研、競品監測、熱點發掘全部可以包裝成收費服務——幫銷售團隊出「開會前 30 日真相」報告，或者做一份以真實互動數據排位的趨勢 Newsletter。

來源：GitHub（mvanhorn/last30days-skill，MIT 授權）

10.阿里開源 OpenCodeReview：識看 Git Diff 的 AI 程式碼審查員

阿里內部用了兩年的 AI 程式碼審查工具正式開源：確定性流程＋LLM Agent 混合架構，逐行給精準評論。項目方自述，在同一底層模型下準確率和 F1 高過通用 Agent，Token 用量只有約九分之一。11 月 17 日登上 GitHub Trending。

3 步上手：
  1. 執行 npm install -g @alibaba-group/open-code-review 裝好 ocr 指令（需 Git 2.41 或以上）；不想另外配模型可用委派模式，npx skills add alibaba/open-code-review 將審查流程交給你現有的編程 Agent。
  2. 原生模式先設定供應商和模型：ocr config provider 再 ocr config model，介面會引導輸入 API Key 並自動測試連通。
  3. 在項目裡面跑 ocr review 審未提交的改動，或 ocr review --from main 審整個分支；想審整個倉庫就用 ocr scan，結果可輸出 JSON 再交給 Agent 跟進。

變現角度：將審查包裝成服務賣給開發團隊——每次合併請求自動審查、逐行指出空指針、線程安全、XSS、SQL 注入等問題；按倉庫或按月收費，賣點是審查成本比用人手或通用 Agent 平得多。（Token 用量數字為項目方自述基準測試結果）

來源：GitHub（alibaba/open-code-review，Apache-2.0 授權）

11.T3 Code：在手機上面遙控家裡電腦的 Claude Code 和 Codex

開源控制面板，將 Claude Code、Codex、Cursor、OpenCode 等編程 Agent 收歸一個介面，在桌面開的任務，出街時用手機批核下一步。11 月 17 日登上 GitHub Trending。

3 步上手：
  1. 裝桌面版（macOS：brew install --cask t3-code；Windows：winget install T3Tools.T3Code），或者跑 curl -fsSL https://t3.codes/install.sh | sh 裝命令列版再打 t3 開伺服器；想試一次不安裝就用 npx t3@latest。
  2. 確保電腦已經登入至少一個 Agent，例如裝 Claude Code 後跑 claude auth login，或裝 Codex CLI 後跑 codex login——T3 Code 不轉售 Token，用你現有的訂閱。
  3. 在手機裝 iOS／Android App，經局域網、Tailscale 或 T3 Connect 連回家裡電腦；每個對話可以獨立用 Git worktree，看完 diff 一鍵提交、推送和開 Pull Request。

變現角度：接急單、改 Bug 不用再綁死在電腦前，在手機批核 Agent 的每一步可以接更多客戶、交貨更快；也可以幫客戶將這套遙距開發流程落地，收設定費。

來源：GitHub（pingdotgg/t3code，MIT 授權）

12.Univer Office SDK：將試算表、文件、簡報嵌進你自己的產品

開源 Office SDK，讓你在自己產品裡面直接內嵌可編輯的試算表和文件，還有公式計算、協作和給 AI Agent 讀寫的 Facade API，不用再靠微軟或 Google。11 月 17 日登上 GitHub Trending。

3 步上手：
  1. 在用 Vite 等打包工具的瀏覽器項目裡面執行 pnpm add @univerjs/presets @univerjs/preset-sheets-core。
  2. 在頁面放一個 <div id="app" style="height: 100vh"></div> 容器，用 createUniver 掛上 UniverSheetsCorePreset，再呼叫 univerAPI.createWorkbook({})，頁面立刻有一個試算表編輯器。
  3. 用 Facade API 操作內容：sheet.getRange('A1:D4').setValues(...) 寫入報價單、公式自動重計，workbook.save() 存成 JSON 快照，下次載入時還原；Agent 也可以用同一套 API 改數。

變現角度：做 SaaS 最貴的其中一環就是文件編輯——用開源 SDK 自己嵌，省回授權費之餘，還可以賣「AI 辦公室」這類產品：讓客戶的 Agent 直接在你的試算表裡面做事。

來源：GitHub（dream-num/univer，Apache-2.0 授權）

13.ChatGPT Work 實戰：將比價這類多步任務整份交給 AI，還要懂得覆核

免費互動教程，教你將 ChatGPT 切換去 Work 模式，叫它比較三間供應商的價錢並起一張有建議的試算表，全程 20 步、約 8 分鐘，還會教你怎樣逐個網站批核和跳過登入。

3 步上手：
  1. 開新對話，在頂部將 Chat／Work 切換掣撥去 Work，再將任務寫成工作單貼入去：列明三間供應商、要收集什麼、成品試算表要有比較頁和建議頁、只用公開頁面、找不到要標明、不可以聯絡或落單。
  2. 逐個網站按 Allow 批核，遇到要登入的網站按 Skip（絕對不要將密碼打入對話）；中途可以用文字糾正方向，例如答它「袋裝價怎樣換算做每立方碼」的提問。
  3. 完成後按「Worked for 6m 12s」看每一步和來源，抽查一兩個數字對回原網站，再叫它「每星期一朝早 7 點做一次」，任務會出現於側欄 Scheduled 裡面。

變現角度：這是最快變現的 AI 服務形態：幫小商戶做每星期供應商比價、發票摘要、報表整理，收月費；重點是懂得覆核數字來源，這個才是客戶願意付費的專業位。注意：網頁版 Work 需要 Plus 或以上計劃，桌面 App 所有計劃（包括免費）都用到。

來源：Stepthrough（Robert Breen，2026-11-17 更新）

14.用 ChatGPT 做微信小遊戲，一個人也能上線賺流水

孫可可引用宋宋老師的文章《我用 ChatGPT 做了一款微信小遊戲》：2026 年 5 月微信小遊戲開發者大會數據，80 多款小遊戲日活超 100 萬，一個季度流水超過 1,000 萬元的微信小遊戲已有 300 多款；文章提供保姆級提示詞方案，一個人用 ChatGPT 也可以做微信小遊戲。

3 步上手：
  1. 先讀原文，拿走文章附帶的保姆級提示詞方案，照著叫 ChatGPT 生成小遊戲代碼。
