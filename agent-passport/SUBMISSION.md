## Agent ID 使用说明（本项目如何使用 Agent ID）
1. **资格门**：注册护照的唯一条件是当前持有 Agent ID。合约实时调用
   SPACE ID 官方注册表（ERC-721）`balanceOf` 校验，与 Four.Meme 等
   已上线门控合约采用同一机制；Agent ID 不可转让，资格无法伪造或借用。
2. **持续身份**：信用分中的「身份分」（20 分）在每次查询时实时复检——
   一旦不再持有 Agent ID，身份分立即归零，护照随之降级，不是「领完即永久」。
3. **可组合身份层**：护照对外暴露 `getScore(address)` / `getPassport(address)`
   标准只读接口，任何合约都可以像 DemoMerchant 一样，在付款/接单前一行调用
   完成「验身」，Agent ID 因此从「一个名字」升级为「全网可调用的信用身份层」。
4. **交互设计**：注册 + 每日打卡驱动 Agent ID 持有者与合约的持续真实交互，
   打卡既是活跃分来源，也是代理「在线证明」。

## 项目介绍（对应评审四维）

### Agent ID 应用深度（30%）
- 不是贴个 Logo 式的集成：Agent ID 是护照的**发行资格、持续有效性、信用锚**
  三重核心。校验做成可插拔接口（IAgentIDVerifier），默认实现直连官方
  SPACE ID 注册表；校验器与注册表地址均可治理升级，面向 Agent ID 体系的
  长期演进。我们还实测并记录了注册表的链上特性（含「不支持按地址反查名字」
  这一真实限制及前端索引解法），见仓库 docs/RESEARCH.md。

### 实用性与合理性（25%）
- 代理经济的真实缺口是「交易对手不可信」：商家不敢收代理的付款，平台不敢
  把任务派给陌生代理。护照提供 0–100 的可验证信用分与一行接入的验身接口，
  分数构成全部来自可验证数据（持证状态、余额档位、护照资历、打卡活跃、
  索引历史背书），并在产品内如实标注 EVM 读不到的数据与近似方法，不造假。
- 成本极低：注册约 $0.0024、打卡约 $0.0013（0.05 gwei 实测），用户可长期使用。

### 产品完成度（25%）
- 合约已完成并通过 35 项本地测试（资格、计分、打卡连续/断签、背书上限、
  商家放行/拦截、校验器热切换、身份分实时归零等全覆盖）。
- 前端为可直接打开的单页应用：连接钱包、我的护照与分项条、注册/打卡、
  商家验身演示（放行/拦截可视化）；已填入主网合约地址，线上官网为
  BSC 主网模式。附演示商家合约，完整演示「付款前验身」闭环。

### 创新性（20%）
- 首个把 Agent ID 从「身份展示」推进到「**可被其他合约调用的信用预言机**」
  的方案：护照分本身成为生态基础设施——收款、任务分发、权益领取、额度
  授信都可以按分设门槛。每日打卡同时构成轻量「代理在线/活跃证明」，
  为后续声誉市场、代理征信与保险定价留下数据层。

## 安全与合规自述
- 合约不托管、不经手任何资产（无 payable、无 transfer/approve 逻辑）；
- 不收集助记词、私钥、API 密钥；注册与打卡必须由用户本人签名发起，
  不绕过任何确认环节；
- 信用分仅为身份信号，产品不承诺任何收益；
- 唯一中心化环节（历史分背书，上限 20 分）已在合约注释、前端页面与
  本材料中三处如实披露，后续将由链下索引（如 BAS）自动回写替代人工。

## 演示脚本（录屏用，约 60 秒）
1. 打开官网，连接持有 fomome.ai 的 Agentic 钱包 → 显示「未注册」；
2. 点击注册护照（钱包确认一次）→ 护照生成，信用分 44 分（新护照示例）；
3. 每日打卡 → 活跃分 +1；推进一天再打卡 → 连续天数 2；
4. 切到验身演示：查询高分代理（93 分）→ 商家放行 ✅；
   查询未注册地址 → 拦截 ⛔；查询新护照（49 分 < 门槛 60）→ 拦截，
   字幕点题：「新代理不是不能用，而是要先攒信用——这正是护照的意义。」
