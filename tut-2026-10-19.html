1.n8n 内容复用引擎：1 篇帖子变成 5 个平台的原生稿

DEV 社区 @haopengai（2026-10-17）的 n8n 工作流拆解：把一篇跑出数据的帖子喂进去，一次产出 5 个平台各自的原生版本。关键设计是"蒸馏节点"抽核心观点、每个平台写"语气契约"、可移植性检查、7 天错峰发布日历。

来源：DEV（2026-10-17）

上手 3 步：
  1. ① 新建 n8n 工作流，先搭"蒸馏"节点：长 prompt + 一好一坏两个例子，逼模型抽出原文唯一核心观点；
  2. ② 为每个平台写"语气契约"节点（小红书口语化、X 短句风），强制每篇脱离原文也能独立成立；
  3. ③ 保留人工决策：只复用已跑出数据的帖子、每篇首行钩子自己改、发布时间自己定。

变现角度：给自媒体/商家做"一稿五发"代运营。作者自述一次全套跑完约 0.05–0.10 美元（GPT-4o-mini 口径），10 分钟产出一周的内容量，成本低到可以按月收服务费；模板本身也可以打包卖。

2.5 个纯本地 AI Agent 的 n8n 工作流：无云端、无月费

作者把 5 个本地优先的 AI Agent 做成可直接导入的 n8n 工作流 JSON，Community Edition 免费自托管：导入→填 CONFIG→激活，首个 Agent 约 15 分钟跑起来（DEV @mohsinakram91，2026-10-17）。

来源：DEV（2026-10-17）

上手 3 步：
  1. ① Docker 一条命令自托管装 n8n Community Edition；
  2. ② 从作者 GitHub 仓库导入 5 个 workflow JSON；
  3. ③ 填好 CONFIG 里的凭证→点 Active→逐个手动触发验证。作者在 n8n 2.43.7 上实测通过（作者自述）。

变现角度："数据不出内网"是卖点：很多小公司不敢把客户数据接云端 API，帮他们本地部署这套 Agent，收一次性部署费 + 按年维护费。

3.第一个本地 AI 自动化：n8n + Ollama 入门流水线

最精简的本地 AI 流水线教学（Medium @arshathhaq97，2026-10-09）：手动触发→Qwen2.5（Ollama 本地跑）→转成文本文件→写盘，4 个节点讲透 n8n 编排 LLM 的逻辑，零 API 费用。

来源：Medium（2026-10-09）

上手 3 步：
  1. ① 装好 n8n 和 Ollama，执行 ollama pull 拉取 Qwen2.5；
  2. ② 拖 4 个节点连起来：Manual Trigger → LLM 节点（指向本地 Ollama）→ Convert to File → Write to Disk；
  3. ③ 写个实用 prompt（比如"列 3 条 Python 自动化的安全用法"）→运行→打开输出文件检查。

变现角度："本地免费 LLM 改造"的敲门砖：帮小团队把原来烧 API 钱的内部小工具（周报生成、文档摘要）换成本地版，每月省下的 API 账单就是你的收费依据，按项目收迁移费。

4.几分钟手写一个 Claude Skill：把重复工作流变成 Agent 的"App"

Skill 就是一个文件夹加一个 SKILL.md，Agent 按 description 自动决定何时加载。Sharbel 的文章给了三种做法（手写/口述让 Claude 代写/录屏让它看），附完整可复制的 YouTube 选题挖掘 Skill 实例（约 2026-10-14 更新）。

来源：Sharbel 个人博客

上手 3 步：
  1. ① 在 Claude 里点 + → Skills → Browse skills → Add → Create a skill；
  2. ② 填 name 和 description，description 写触发关键词（比如"当我说 youtube-pockets 时用"）而不是泛泛描述；
  3. ③ 把手工流程写成步骤——直接套用文章里 7 步选题挖掘模板（vidIQ 搜→近 4 周→outlier 2x→5 万播放→分组找标题格式→取前 5），改成自己的业务流程。作者实测一次搜索筛出 22 条达标视频、产出 4 个选题池（作者自述）。

变现角度：把客户/团队每周重复解释 10 分钟的流程打包成 Skill，卖"AI 效率改造"服务。安全提醒：装别人的 Skill 前先让 Agent 通读代码，检查网络调用和凭证读取。

5.AI 自动化 vs AI Agent：同一个客服任务，3 种解法实测对比

把"客服消息分类"这个任务在 n8n 里搭 3 遍实测：纯规则 4 条错 2 条、单 AI 步骤 4/4 全对约 3 秒跑完、有边界的 Agent 查政策+查订单+人工确认，22 秒 3 次模型调用；最后给出 3 问选型法则（YouTube，约 2026-10-16 发布）。

来源：YouTube（约 2026-10-16）

上手 3 步：
  1. ① 先搭 Level 1 纯规则版：If 节点按关键词分流，跑 4 条真实消息看误判率；
  2. ② 升级到 Level 2：加一个 AI 分类节点，对比准确率和耗时（视频里 4/4 全对、约 3 秒）；
  3. ③ 只有需要查政策、查订单、人工确认的场景才上 Level 3 的 Agent，并设人工审批、每日限额、预算上限。注意：以上数字均为视频作者自建演示数据（样本店铺、样本订单），非真实客户数据。

变现角度："选型框架"本身就是接单话术：帮客户选最便宜够用的方案而不是最贵的，用实测数据证明"不是所有活都需要 Agent"，靠实在拿长期单。

Google Research 的递归 Agent 框架（2026-10-19 登 GitHub 日涨星榜第 2）：任务级自动提议改写并实测验证，证据驱动的经验跨任务复用；自带 OpenCode/Codex 执行器和 JobBench 评测集。

项目地址：https://github.com/google-research/harness2

上手 3 步：
  1. ① git clone 仓库并按 README 装 Python 依赖；
  2. ② 选执行器：OpenCode 或 Codex 二选一；
  3. ③ 在自带 JobBench 上跑一轮任务，观察 harness 如何基于行为对比自我改进。涨星数 +6,080 为第三方榜单 ghtrends.dev 2026-10-19 日数据（转述），功能描述来自仓库说明。

变现角度：偏开发者向："自我改进 Agent"是前沿方法论，懂的人少，适合做高阶 AI 工程咨询或内训；先用它给自己的 Agent 提效，案例就是获客材料。
