教程速遞｜2026-11-09

1.用 Claude Code 驗證／斃掉創業點子：25 步免費開源驗證流水線

作者把自己驗證創業點子的完整流程做成了一個免費 MIT 開源 Claude Code 技能（founder-pipeline），25 步串行跑完需求、付費意願、定價、競品等檢查，通不過就斃掉、省下開發時間；他自己的 AI 教練點子 4 項初檢全掛、只得 2.5/10 分。

3 步上手：
  1. 安裝技能：claude plugin marketplace add marian-kamenistak/founder-pipeline，再 claude plugin install founder-pipeline@founder-pipeline
  2. 對自己的點子跑一遍流水線，按提示逐項簽字確認
  3. 只看兩道「錢關」（定價／利潤、付費意願）的結論——不通過就先不寫代碼

變現角度：最大的省錢是「不做錯的產品」——作者給自己的點子設了 40 小時上限（相當於 €8,000–9,600 的諮詢時間），驗證前置避免把幾週開發時間燒在沒人付費的點子上；流程本身也可包裝成「創業驗證」諮詢服務賣給想做產品的客戶。

來源：DEV Community

2.n8n 免費每日新聞摘要工作流：不用搜索 API，每天自動發郵件簡報

用免費社區節點 n8n-nodes-agentsearch（每天 25 次免費搜索、不用 API key）搭一個定時工作流，每天早上按你的主題搜網、去重、讓模型寫摘要、發郵件，附可直接導入的 workflow JSON。

3 步上手：
  1. 自托管 n8n 裡裝節點：cd ~/.n8n/nodes && npm install n8n-nodes-agentsearch
  2. 按「定時觸發 → 主題列表 → AgentSearch 免費搜索 → 按 URL 去重 → 摘要提示詞 → 發郵件」的節點順序搭好
  3. 把主題換成你跟蹤的行業詞（如 AI、副業），設每天早上 7 點跑

變現角度：零成本做出「行業早報」類內容產品——可做成付費 Newsletter、社群日報，或接「幫企業盯競品／行業動態」的代跑服務；省的是每天手動刷新聞的時間。

來源：DEV Community

3.你的 LLM 不是 AI Agent：Python 工具調用從零搭一個真 Agent

講透工具調用（function calling）架構的入門教程：LLM 只負責「決定調哪個函數」，你的 Python 程序負責執行並把結果還給模型，照著做能搭出一個會用計算器的任務助手，理解 Agent 的底層結構。

3 步上手：
  1. 裝依賴 pip install openai python-dotenv，建 main.py／tools.py
  2. 定義一個工具（如 calculator），把它的 JSON schema 交給模型
  3. 跑起來看模型如何自主決定何時調工具，再把計算器換成你自己的業務函數（如查訂單、發郵件）

變現角度：這是接 AI Agent 定制開發單子的基本功——會搭工具調用就能給小企業做「能查庫存、能回客戶」的客服／助理 Agent，按項目收費；也是理解市面 Agent 產品的地基，避免被概念割韭菜。

來源：DEV Community

4.用 AI Agent 一句話搭帶推薦裂變的註冊 waitlist：數據庫＋登錄＋郵件一次配齊

通過一個 MCP 連接讓 Cursor／Claude Code 自動配好產品上線前的 waitlist 後端：Postgres 存註冊、Redis 做推薦排行榜和限流、郵件確認、推薦獎勵，CloudHike 新賬號有 $10 免費額度、不用綁卡。

3 步上手：
  1. 在 CloudHike 連 MCP：claude mcp add --transport http --scope user cloudhike https://cloudhike.dev/api/mcp
  2. 用 npx create-next-app@latest waitlist 起前端
  3. 直接對 Agent 說「用 cloudhike MCP 搭一個帶推薦的 waitlist 後端」，讓它建表、接登錄和郵件

變現角度：每個新產品上線前都要 waitlist——這是一次性可復用的「上線標配」，能打包成給獨立開發者的付費上線服務，或自己每個產品都復用，省掉每次 4 個服務的手動接線時間。

來源：DEV Community

5.用 Python 和 OpenAI Agents SDK 做你的第一個 AI Agent（任務助手）

零基礎友好的 Agent 入門：用 OpenAI Agents SDK 做一個任務管理助手，覆蓋建 Agent、給工具、理解工具調用、運行和改進全流程，代碼量小、適合第一次動手。

3 步上手：
  1. mkdir python-ai-agent，建虛擬環境並 pip install openai-agents
  2. 寫 main.py，用 Agent + Runner.run_sync 定義一個任務助手並給它第一個工具
  3. 跑起來測試，再按教程的「改進」一節加更多工具（如提醒、日程）

變現角度：學會後可把「任務助手」換成面向具體人群的版本（如律師助理、電商客服）做成小產品或接單；對非技術用戶，這也是理解「Agent 能幫我幹什麼」的最便宜入口。

來源：DEV Community

6.「我讓 Claude 每月賺 $200」：10 天實測，37 本 KDP 謎題書上架、銷售額 $0 的誠實記錄

作者給 Claude Code 下指令「每月至少賺 $200，否則取消訂閱」，每天只花幾分鐘人工，10 天後產出 37 本按需印刷謎題書、7 本日文經典英譯、Gumroad／BOOTH／Payhip 三個店面和每日 Pinterest 發布——但銷售額是 $0，文章如實記錄了每道牆（KDP 每週上新限額、支付綁定、Cloudflare 人機驗證）。

3 步上手：
  1. 讓 AI 用代碼批量生成數獨／迷宮／找詞謎題 PDF（不用庫存、單本利潤 $2–3）
  2. 走 Amazon KDP 上架紙質書（新賬號每週約限 2 本紙質＋2 本電子，注意週日 UTC 零點重置），同時掛 Gumroad 賣可打印 PDF
  3. 每天用 Pinterest 發圖引流，設週六晚定時任務批量上傳下一批

變現角度：按需印刷是「一次製作、長期賣」的典型：量起來後單本 $2–3 的利潤靠書目數量堆；文章的價值恰恰是反 hype——先看清限額和支付牆再投入，避免幻想「AI 自動賺錢」。適合做 KDP 副業的避坑指南。

來源：Medium（@yuyusub741）

7.OpenMAIC：清華開源的多智能體互動課堂，一句話把任何主題變成 AI 課堂

清華 THU-MAIC 團隊開源的 OpenMAIC（42,800+ stars），輸入一個主題或上傳文檔，就能生成由 AI 老師＋AI 同學授課的互動課堂：講義、測驗、互動模擬、白板講解、語音旁白，還能一鍵導出 PPTX 或離線 HTML。

3 步上手：
  1. 克隆倉庫 git clone https://github.com/THU-MAIC/OpenMAIC.git，按 README 用 pnpm 安裝（需 Node.js 22.19+、PostgreSQL 16）
  2. 在 openmaic.yml 配一個模型 key（支持 OpenAI、Anthropic、Gemini、DeepSeek、Qwen、Kimi 及本地 Ollama）
  3. 輸入主題或上傳 PDF，生成課堂，或直接去 open.maic.chat 申請訪問碼免部署體驗

變現角度：可做「AI 課程定制」服務——幫培訓機構／企業把內部文檔轉成互動課程收費；也可用來批量生產課程內容再賣課；注意許可證為 AGPL-3.0，對外提供服務需留意合規（或聯繫團隊拿商業授權）。

來源：GitHub

8.Claude Code vs Cursor vs Copilot：2026 年三選一實測對比

11 月 5 日更新的橫向對比：Claude Code 是終端 Agent、Cursor 是 AI 原生編輯器、Copilot 是多編輯器助手，附三者的實測命令和定價（Claude Pro $20/月起含 Claude Code），並給了一個「一下午在自己代碼庫上實測三款」的方法。

3 步上手：
  1. 從待辦裡挑三個真實任務（修小 bug、跨文件小功能、帶測試的重構）
  2. 每款工具各建一個分支跑同一批任務，記錄完成質量和耗時
  3. 按場景選：終端／腳本自動化選 Claude Code 或 Copilot CLI，日常寫代碼選 Cursor

變現角度：選對工具直接省訂閱費（避免三份都交錢）和返工時間；對接單開發者，熟悉三款工具的差異本身就是接「AI 結對編程」「代碼審查」類單子的賣點。

來源：DEV Community

9.AI Agent 還是自動化？5 個問題幫你判斷（Claude Code 篇）

引用 Anthropic 官方《Building Effective Agents》的判斷框架：步驟能提前寫死的用腳本，需要臨場判斷的才上 Agent；附 5 個自測問題和「先腳本、只在腳本反覆失敗處加 Agent」的省錢策略。

3 步上手：
  1. 挑一個你每週重複的任務，問自己「步驟今天能完整寫下來嗎？能覆蓋九成情況嗎？」——能就寫腳本
  2. 不能的，拆出「需要判斷」的環節，只在那幾處用 Claude Code headless 模式（claude -p）加短工具白名單
  3. 跑在 GitHub 上的任務直接用 Claude Code GitHub Action

變現角度：避免為每個任務都上 Agent 而燒掉 API 賬單——腳本幾乎零成本，Agent 只用在刀刃上；幫客戶做自動化時，這個判斷力本身就是報價的依據（不讓客戶為不需要的「智能」付費）。

來源：DEV Community

10.賣 Canva 輪播圖模板：一個 $127/月的副業算法（附可直接用的提示詞）

作者的 AI 副業週報：做一套 10 頁 Instagram 輪播圖模板掛 Gumroad 賣，按 $12/套×每月 15 單算，扣掉 Gumroad 手續費（10%+$0.50/單）和 Canva 付費版約 $18/月，到手約 $127/月；作者明確標註這是「假設數、不是實績」，首月真實預期是 0–3 單。

3 步上手：
  1. 用 Canva 付費版做一套 10 頁輪播模板並生成模板鏈接
  2. 用 ChatGPT（免費版即可）寫配套文案和產品描述，掛 Gumroad 定價 $12
  3. 在 Instagram／小紅書持續發「模板效果」內容引流，復用同一套模板換主題出新品

變現角度：模板是「做一次、賣多次」的數字資產，邊際成本幾乎為零；關鍵是先驗證需求再批量做——作者提醒首月可能負收益（Canva 月費先扣），別一上來就囤幾十套。

來源：Medium（Donlee）

11.X @Sunkeke_AI：Reddit 運營全流程即插即用模板

13.X @liangzhu_AI：開發模型選型實測——Codex 10 分鐘 vs 國產模型 5.5 小時

良竹的開發模型選型實測對比：同一開發工作在 Codex 上約 10 分鐘完成，用 GLM 或 DeepSeek 卻要 5.5 小時，因此他多次嘗試換回國產模型後仍回到 Codex。對獨立開發者選擇主力編碼模型有直接參考價值。（數據口徑：博主自述實測）

3 步上手：
  1. 在自己的項目裡挑一個真實任務，分別用 Codex 與國產模型各跑一遍，記錄完成時間與返工次數
  2. 算一筆賬：模型差價 vs 你的時薪，貴的模型如果省 5 小時反而更便宜
  3. 主力模型定下來後，把常用提示詞與工作流固化，別頻繁切換

變現角度：選型錯了，開發時間直接翻 30 倍——花半天做一次自己的實測對比，比看十篇評測都有用；接單開發者尤其要算清「模型成本 vs 時間成本」這筆賬。

來源：X @liangzhu_AI

14.X @MoonInAI：實地拜訪廣東 OPC 社區——除深圳外入駐率低、補貼難拿

MoonInAI 實地拜訪廣東多個 OPC 社區後的觀察：除深圳外大部分社區入駐率很低，省級補貼亦全部向深圳傾斜、其他地方很難拿到；引用的觀點是「OPC 跑不通，只有公司能跑通」，屬於創業選址與模式避坑判斷。

3 步上手：
  1. 做選址決策前，先實地走訪目標社區，別只看招商宣傳
  2. 問清楚補貼的實際發放門檻與地域限制，再算投入產出
  3. 模式上優先考慮「公司化運營」而非只靠社區流量

變現角度：選址與補貼是創業最容易踩的坑——別人實地跑出來的結論，能幫你省下一筆試錯租金與時間；做線下／社區相關副業前，先看這類一手觀察。

來源：X @MoonInAI

15.X @HaileyAILabs：Sherlock——一個用戶名查遍 400＋ 個網站

GitHub 10.5 萬 Star 的開源工具 Sherlock：輸入一個用戶名，即可在 400 多個網站查找同名賬號，連已遺忘的論壇、社區賬號也有機會找回。可用於副業調研、用戶名佔用檢查及競品賬號查找。

3 步上手：
  1. pip install sherlock-project 或直接克隆 GitHub 倉庫
  2. 跑 sherlock <用戶名>，看目標用戶名在哪些平台已被佔用
  3. 用它做競品調研：查對手在哪些平台有賬號、活躍在哪裡

變現角度：註冊新品牌前先查用戶名佔用，避免名字撞車；做競品調研時，一個命令就能摸清對手的平台佈局，省的是逐個平台手動搜索的時間。

來源：X @HaileyAILabs
