5.Claude Code 实战手册：10 条经官方文档核对的提效经验

对照 Anthropic 官方文档逐条核对的 Claude Code 经验清单，包括 CLAUDE.md 要短、按路径分规则、Hooks 是锁而非建议、两次修不好就清空重来等。

来源：Substack《What Survives in AI》

  2. 把文件类型规则放进.claude/rules/ 按路径生效
  3. 同一个 bug 修两次失败就 /clear，一次给清错误和“别试什么”

变现角度：编程效率直接等于接单量，少走弯路就是多赚钱；手册里的用法也可整理成教程内容变现。

7.Claude Code 里 Skill 和 Workflow 到底用哪个？实测对比告诉你

用 Claude Code v2.1.318（2026-11-04 实测）在同一个演示项目上对比 Skill 与 Workflow：Skill 是 Claude 按文字指令临场决定下一步，Workflow 是脚本决定每一步的执行顺序。

来源：AI Parabellum

3 步上手：
  1. 建一个含三个带 bug 的 Python 文件的演示文件夹
  2. 写一个 Skill 让 Claude 按固定格式审一个文件
  3. 再写一个 Workflow 做多文件并行审查加汇总，对比两者在你任务上的效果

变现角度：大任务用 Workflow 可复用、可卖给团队当标准化流程；小任务用 Skill 更灵活，选错会浪费大量 token 和时间。

来源：AI Parabellum

变现角度：提案、技术方案、商业计划书这类文档是高价服务，用 Skill 批量产出能接更多单；写得好的文档模板本身也能卖。

16.Sunkeke：做游戏精灵表，让 Codex 当像素画师而不是主程序员

@Sunkeke_AI 11 月 7 日转帖分享一篇被 Codex“暴虐”后的心得：制作游戏精灵表（sprite sheet）的最优解不是让 Codex 当主程序员写程序，而是让它当像素画师出图。换言之，关键在于重新分工，而非一味要求模型写完整程序。

来源：X @Sunkeke_AI

3 步上手：
  1. 把任务拆开：美术出图交给 Codex，程序逻辑自己写或另起会话
  2. 先让 Codex 出一张精灵表小样，确认风格统一再批量
  3. 批量出图后人工检查边缘与透明通道，再进游戏引擎

变现角度：给 AI 分工是接单的基本功：让模型干它最擅长的一环、人工把关衔接处，比“一个提示词出完整游戏”靠谱得多，交付成功率直接决定能不能收到尾款。
