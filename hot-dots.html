OpenAI Dots：AI Agent 从"接任务"走向"接责任"

2026-10-11 · 猪猪侠玩AI · 中文首测

9 月底 OpenAI 开发者大会（DevDay 2026）上，除了模型更新，还有个容易被忽略的东西：Dots。看懂它，就看懂了 AI Agent 的下一个形态。

一、差在哪：一个例子

以前的 Agent：

你："帮我整理这周的客户反馈。"
Agent：整理完发你。任务结束。

Dots：

你："以后持续负责客户反馈。"
Dot：之后不用你再下指令。它自己发现"这个问题这周又出现了 5 次"，分析原因，小的改动自己改完测完，大的决定带回来找你拍板。

差别不在"能干多少"，而在"没指令时会不会主动看"。OpenAI 把这种能力叫 proactive research（主动研究）。

二、产品形态

每个 Dot 由 GPT-6 Astra 驱动，拥有自己的云端电脑和浏览器，能通过 OpenAI 的插件生态连接 4000+ 应用。你可以给它命名、定目标、定偏好和标准，再连上它干活需要的应用。

OpenAI 给它配了三种视图：进行中、排程、已完成。你可以调周期性工作的执行时间、通知方式，随时暂停。交出去不等于失控，这是它和"全自动"最大的区别。

三、和前辈们的对比

  • Rabbit / 早期硬件 Agent：噱头大于可用，停在演示层。
  • Manus / 通用 Agent：强在单次任务的完成度，但做完就结束。
  • Claude 的托管 Agent：Anthropic 刚加了动态工作流，单次可并行 1000 个子代理，强在"规模"，但同样是被动响应。
  • Dots：强在"持续"。VentureBeat 把这种模式称为 workflow ownership（工作流责任制）——人定目标和标准，AI 持续盯着底层变化、跟着更新。

四、Space：进团队的那一步

同步发布的 ChatGPT Space，把这套模式从个人带进团队：团队成员、ChatGPT 和 Dot 共用项目知识，页面和已连接的工具保持同步。比如项目页自动从 Slack、邮件、日历抓待办，Dot 随状况更新负责人和期限。

AI 的工作第一次从"某人的聊天记录"变成了"团队共同维护、持续变动的成果"。这一步的意义不亚于 Dots 本身。

五、限制和冷静

  • 目前一个人只能建一个 Dot，之后开放多个和专用版
  • 长时间运行 + 记忆 + 持续工作 = 持续的 token 账单。Anthropic 官方都提示多代理工作流"消耗大量 token，先小规模测试"
  • 权限是核心风险：能操作你电脑、连你应用的 Agent，权限控制做不好就是灾难。OpenAI 这次把权限控制做成了产品的一部分，值得肯定，但实战中仍需谨慎

六、对打工人的影响

可以开始盘一盘了：你的工作里，哪些是"一次性任务"，哪些是"需要长期盯的事"？后者——客户反馈、竞品监控、数据日报、内容更新——正是 Dots 这类产品要吃掉的部分。先被影响的不是"写"，而是"盯"。

一句话总结：Agent 的竞争正在从"单次做得好"转向"长期靠得住"。接任务是功能，接责任才是产品。
